一、数据生成流程
================================================================================

脚本执行顺序：
01_parse_questions.py          → 解析xlsx生成基础问题JSON
02_expand_questions.py         → 调用OpenAI生成问题变体
03_query_models.py             → 批量调用国内大模型API回收应答
04_analyze_results.py          → 离线统计分析 + 相似度计算
05_extract_recommendations.py  → LLM提取推荐信息 + 分类统计 + 统一提及率报表
06_build_knowledge_base.py     → 产品资料提取为结构化知识库
07_verify_accuracy.py          → 知识库校对（keyword/llm模式）
08_generate_report.py          → 调用GPT生成完整分析报告（手动触发）

关键配置文件：
config/brands.yaml             → 品牌词典 + 分析框架关键词配置
  - brand_999                  → 999产品及别名（合并原brand_keywords）
  - known_brand_competitors    → 品牌竞品名（扁平列表，用于子串匹配）
  - generic_names              → 通用名（扁平列表，不分品牌的药品通用名）
  - product_name_map           → 产品短名→标准名映射（如 小感→小儿感冒颗粒）
  - category_keywords          → 品类关键词（感冒药/止咳药等）
  - component_keywords         → 成分/品类级关键词（用于过滤非具体产品）

修改brands.yaml后重跑04+05即可更新所有分类结果，无需重跑LLM。

二、04脚本生成的报表（results/analysis/）
================================================================================

04脚本为纯计算，不调用LLM。基于parser.py关键词匹配和统计聚合。

--------------------------------------------------------------------------------
2.1 raw_data.csv — 原始数据总表
--------------------------------------------------------------------------------
作用：所有问答的完整原始数据，方便回查和排错。

字段：
- 问题ID          问题唯一标识，如 ganmaolin_q1_overall
- 产品            产品短名，如 感冒灵、小感、强枇
- 产品代码        产品英文代码，如 ganmaolin
- 问题层级        q1_overall / q2_detail / q3_scenario1 / q4_scenario2 / q5_top3 / negative_safety
- 问题类别        accuracy / mention_recommend / negative_safety
- 是否变体        True/False
- 变体来源        原始问题ID（变体才有值）
- 变体类型        colloquial / no_brand / demographic / alt_angle / negative_safety
- 问题            完整问题文本
- 模型            deepseek / qwen / hunyuan / doubao
- 模型名称        DeepSeek / 通义千问 等
- 联网            是/否
- 轮次            1-5
- 应答            完整应答文本
- 应答字数        应答文本长度
- 响应耗时ms      API响应时间
- 引用源URL       联网模式引用的URL（分号分隔）
- 引用源标题      联网模式引用的标题（分号分隔）
- 引用源数量      引用源条数
- 时间戳          API调用时间

--------------------------------------------------------------------------------
2.2 stability_report.csv — 回答稳定性分析
--------------------------------------------------------------------------------
作用：衡量同一问题多轮回答的品牌提及一致性。

字段：
- 问题ID          问题唯一标识
- 产品            产品短名
- 模型            deepseek / qwen / hunyuan / doubao
- 联网            是/否
- 轮次数          该组合的回答轮次数
- 品牌提及Jaccard均值   多轮推荐产品集合的平均Jaccard相似度（0-1）
- 推荐排序完全一致       多轮的推荐排序是否完全相同

--------------------------------------------------------------------------------
2.3 search_diff_report.csv — 联网vs不联网差异分析
--------------------------------------------------------------------------------
作用：对比同一问题联网和不联网下的推荐差异。

字段：
- 问题ID          问题唯一标识
- 产品            产品短名
- 模型            deepseek / qwen / hunyuan / doubao
- 联网999提及率   联网模式下999品牌提及率
- 不联网999提及率 不联网模式下999品牌提及率
- 提及率差异      联网-不联网的差值
- 仅联网出现的品牌    仅在联网模式下被推荐的品牌
- 仅不联网出现的品牌  仅在不联网模式下被推荐的品牌

--------------------------------------------------------------------------------
2.4 source_report.csv — 信息源域名汇总
--------------------------------------------------------------------------------
作用：联网模式下模型引用了哪些网站，按域名统计频次。

字段：域名、引用次数

--------------------------------------------------------------------------------
2.5 source_detail_report.csv — 信息源明细
--------------------------------------------------------------------------------
作用：联网模式下每条引用的详细信息。

字段：问题ID、产品、模型、域名、标题、URL

--------------------------------------------------------------------------------
2.6 variant_sensitivity_report.csv — 问法敏感度分析
--------------------------------------------------------------------------------
作用：对比原始问题和变体问题的999提及率差异。

字段：基础问题ID、产品、模型、联网、原始999提及率、变体999提及率、差异

--------------------------------------------------------------------------------
2.7 cross_model_consistency.csv — 跨模型一致性分析
--------------------------------------------------------------------------------
作用：同一问题在不同模型间的品牌提及一致性。

字段：
- 问题ID、产品、联网、模型数
- 品牌并集数      所有模型提及品牌的并集大小
- 品牌交集数      所有模型共同提及品牌的交集大小
- 品牌一致度      交集/并集
- 各模型一致提及  所有模型都提及的品牌列表
- {model}_999提及率   各模型的999提及率（动态列：deepseek/doubao/hunyuan/qwen）

--------------------------------------------------------------------------------
2.8 accuracy_summary.csv — 准确率汇总（供人工评分）
--------------------------------------------------------------------------------
作用：Q1-Q2应答的人工评分模板。

字段：问题ID、产品、模型、联网、轮次、问题、应答、人工评分（空）、备注（空）

--------------------------------------------------------------------------------
2.9 optimization_report.csv — 优化建议
--------------------------------------------------------------------------------
作用：自动诊断各产品×模型的薄弱环节。由05脚本覆盖更新。

字段：产品、模型、优先级（高/中/低）、问题数、发现、主要竞品、建议方向

--------------------------------------------------------------------------------
2.10 unknown_brands.csv — 未收录品牌候选
--------------------------------------------------------------------------------
作用：词典中未收录但反复出现的药品名，供审核补充到brands.yaml。

字段：候选品牌名、出现次数（≥2次才输出）

--------------------------------------------------------------------------------
2.11 answer_similarity.csv — 多轮回答文本相似度
--------------------------------------------------------------------------------
作用：TF-IDF衡量同一问题多轮回答的文本相似度。

字段：
- 问题ID、产品、模型、联网、轮次数
- 平均字数        多轮回答的平均字数
- 字数标准差      多轮回答字数的标准差
- TF-IDF相似度    基于TF-IDF向量的文本相似度（0-1）
- LLM校对建议策略 07脚本的建议发送策略
- 问题            完整问题文本

三、05脚本生成的报表（results/analysis/）
================================================================================

05脚本先用LLM（DeepSeek）提取推荐信息（支持断点，已跑完自动跳过），
然后基于提取结果做纯计算的统计分析和分类。
分类逻辑全部依赖brands.yaml配置，修改yaml重跑即可。

--------------------------------------------------------------------------------
3.1 recommendation_detail.csv — 推荐提取明细（LLM生成）
--------------------------------------------------------------------------------
作用：LLM从每条Q3-Q5应答中提取的结构化推荐信息。所有后续报表的数据源。
生成：LLM提取（DeepSeek V3.2），支持断点续跑

字段：
- 问题ID          问题唯一标识
- 产品            场景所属的产品短名
- 模型            原始回答的模型
- 联网            是/否
- 轮次            1-5
- 推荐排名        该产品在推荐中的排名（1为最强）
- 推荐产品        被推荐的产品名称（保持原文写法）
- 推荐强度        strong(强推荐) / moderate(可选) / mention(仅提及) / caution(警告)
- 推荐理由        从原文提取的推荐理由（30字以内）
- 品类            产品品类（LLM判断）

--------------------------------------------------------------------------------
3.2 brand_generic_detail.csv — 推荐产品分类明细
--------------------------------------------------------------------------------
作用：对recommendation_detail中每条推荐产品标注名称类型，覆盖全部Q3-Q5数据。
生成：纯关键词匹配（基于brands.yaml配置）

名称类型分类逻辑（优先级从高到低）：
1. 999品牌     — 推荐产品命中 brand_999 名称或别名
2. 竞品品牌    — 推荐产品命中 known_brand_competitors
3. 成分品类级  — 推荐产品命中 component_keywords，不是具体产品
4. 通用名      — 以上都未命中，为行业通用药品名（可能是任何厂家的产品）

字段：
- 问题ID、产品、问题层级（Q3/Q4/Q5）、模型、联网、轮次
- 推荐排名        原始推荐排名
- 推荐产品        产品名称原文
- 名称类型        999品牌 / 竞品品牌 / 通用名 / 成分品类级
- 推荐强度        strong / moderate / mention / caution
- 是否推荐        1(strong/moderate) / 0(mention/caution)
- 推荐原因        推荐理由（仅是否推荐=1时有值）

--------------------------------------------------------------------------------
3.3 mention_report.csv — 提及率报表
--------------------------------------------------------------------------------
作用：按产品×模型×联网×问题层级统计999品牌的提及情况。
生成：基于recommendation_detail分类结果统计

字段：
- 产品            产品短名
- 模型            deepseek / qwen / hunyuan / doubao
- 联网            是/否
- 问题层级        Q3/Q4/Q5等
- 总回答数        该维度组合下的应答总数
- 提及999次数     推荐产品命中999品牌关键词的次数
- 提及率          提及999次数 / 总回答数

注：提及次数可能>总回答数，因为一条应答中LLM可能提取出多个推荐产品。

--------------------------------------------------------------------------------
3.4 rec_overview.csv — 统一推荐总览（核心报表）
--------------------------------------------------------------------------------
作用：999本品、品牌竞品、通用名统一在一张表，口径一致。
生成：基于brands.yaml子串匹配 + 位置级最长匹配去重

统计口径：
- 按应答去重：同一条应答中同一标准产品名只计1次，取最高推荐强度
- 以全量应答为分母，可直接算提及率/强推荐率
- 联网/不联网分开统计，可直接对比联网影响

字段：
- 产品、模型、联网、应答总数
- 排名             该 (产品×模型×联网) 内按提及次数降序排名
- 被推荐产品       标准产品名（经brands.yaml子串匹配归一化）
- 名称类型         999品牌 / 品牌竞品 / 通用名 / 成分品类级 / 未识别
- 提及次数 / 提及率
- 强推荐次数 / 强推荐率
- 可选次数

--------------------------------------------------------------------------------
3.5 rec_reasons.csv — 推荐理由分析
--------------------------------------------------------------------------------
作用：999产品和竞品各自被推荐的高频理由。

字段：类型（999产品/竞品）、推荐理由、出现次数（各取Top30）

--------------------------------------------------------------------------------
3.6 dashboard.csv — 总览Dashboard（05脚本覆盖更新）
--------------------------------------------------------------------------------
作用：全局核心指标一张表，基于Q3-Q5 LLM提取数据。

字段：
- 产品            产品短名
- 模型            deepseek / qwen / hunyuan / doubao
- 总回答数        Q3-Q5应答总数
- 999提及率(整体)      整体999品牌提及率
- 999提及率(不联网)    不联网模式下999品牌提及率
- 999提及率(联网)      联网模式下999品牌提及率
- Top3推荐率           999品牌进入推荐Top3的比率
- 999平均排名          999品牌在推荐列表中的平均排名
- 回答稳定性(Jaccard)  多轮回答的品牌提及Jaccard相似度
- Top3竞品             排名前3的竞品品牌

四、07脚本生成的报表（results/analysis/）
================================================================================

07脚本基于知识库对Q1-Q2应答进行准确性校对。
方向：应答→知识库（只查错，不查遗漏）。
按 (问题ID × 模型 × 联网) 分组，每组多轮回答一起发给DeepSeek校对。
10并发，需手动触发执行。

--------------------------------------------------------------------------------
4.1 accuracy_llm_verify.csv — LLM校对明细
--------------------------------------------------------------------------------
作用：DeepSeek对AI回答中每条事实性陈述的逐条校对结果。
生成：07脚本（调用DeepSeek API）

字段：
- 问题ID          问题唯一标识
- 产品            产品短名
- 模型            deepseek / qwen / hunyuan / doubao
- 联网            是/否
- 轮次数          该分组包含的回答轮次数
- claim           AI回答中的事实性陈述（30字以内）
- rounds          该陈述出现在哪几轮（如 [1,2,3,5]）
- verdict         correct(与知识库一致) / wrong(与知识库矛盾) / unverified(无法判断)
- evidence        知识库中的对应依据原文（50字以内）
- correction      如果wrong，正确说法（50字以内），否则为空

--------------------------------------------------------------------------------
4.2 accuracy_llm_summary.csv — LLM校对汇总
--------------------------------------------------------------------------------
作用：按产品×模型×联网汇总校对结果。
生成：07脚本（基于明细表聚合）

字段：
- 产品、模型、联网
- 总陈述数        AI回答中被提取的事实性陈述总条数
- 正确            verdict=correct 的条数
- 错误            verdict=wrong 的条数
- 无依据          verdict=unverified 的条数
- 准确率          正确 / (正确+错误)，unverified不计入分母
- 主要错误        Top3错误摘要（claim→correction格式）

注：4.1-4.2需运行07脚本后才会生成，当前目录中仅有accuracy_summary.csv（04脚本生成的人工评分模板）。

六、建议分析顺序
================================================================================

1. 全局概览     dashboard.csv → 一张表定位全局强弱
2. 推荐总览     rec_overview.csv → 999/竞品/通用名统一对比（按联网拆分）
3. 提及分析     mention_report.csv → 按产品×模型×联网×层级查看999提及率
4. 分类下钻     brand_generic_detail.csv → 逐条查看推荐产品分类
5. 推荐理由     rec_reasons.csv → 999 vs 竞品的推荐理由对比
6. 联网影响     search_diff_report → source_detail_report
7. 稳定性       stability_report（品牌Jaccard）+ answer_similarity（文本TF-IDF）
8. 问法敏感度   variant_sensitivity_report
9. 跨模型对比   cross_model_consistency
10. 准确率校对  运行07脚本 → accuracy_llm_verify / accuracy_llm_summary
11. 优化建议    optimization_report
12. 完整报告    运行08脚本生成AI分析报告

七、关键词分类校准流程
================================================================================

如发现分类不准确：

1. 编辑 config/brands.yaml 中对应配置节
   - 999品牌词不对  → 改 brand_999（名称或aliases）
   - 品类词不对     → 改 category_keywords
   - 通用名不对     → 改 generic_names
   - 竞品分类不对   → 改 known_brand_competitors
   - 成分词误判     → 改 component_keywords
   - 产品名映射缺失 → 改 product_name_map

2. 重跑（不会触发LLM）
   python scripts/04_analyze_results.py
   python scripts/05_extract_recommendations.py

3. 检查结果，重复以上步骤直到满意
